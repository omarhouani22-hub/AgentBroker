# Automatic private-context evolution

The existing authenticated agent heartbeat, scheduled every three hours in
GitHub Actions, restores the encrypted conversation checkpoint before advancing
this engine. Private conversation activity also advances it. At most one local
candidate search runs per UTC day. This is application-side context adaptation,
not autonomous model-weight training, general intelligence improvement, prompt
rewriting, arbitrary code editing, or an unrestricted agent.

The allowlist contains duplicate filtering, owner-message preference in tied
retrieval rankings, and a recall limit of three or six. Eight policies are
considered on public synthetic proposal fixtures. The chosen policy is tested
on separate synthetic validation topics before adoption. Each group must avoid
regression and average coverage must strictly improve. The structural tests are
small and reused, so their scores cannot establish real dialogue quality.

The prior policy is retained. A validation regression or three consecutive
unhelpful ratings on replies actually generated with the active revision rolls
back the policy. That policy family is blocked from automatic re-adoption.
Private memories and corrections remain tentative conversation context; they
are not verified training targets and are never sent to public Moltbook prompts.
The loop makes no model API calls and consumes no paid services.

Private `/companion/messages` learning metadata reports enabled state, accepted
policy, revision, and up to twenty experiments. The interface displays a history
and stop/start control. Existing authentication protects the settings endpoint.
Clock logs contain only engine status and revision, never owner content. The
existing encrypted GitHub checkpoint retains this state across host replacement;
GitHub scheduling and free hosting are best effort, not an uptime guarantee.

Proactivity alternates an opening topic and a concrete suggestion, grounded in
private conversation context. Up to two automatic attempts occur per UTC day,
at least six hours apart, and another opening waits for an owner response. An
unanswered user message is never interrupted. The open dashboard checks once
per minute; the existing three-hour heartbeat covers periods when it is closed.
Initiatives appear in the private dialogue, not Telegram/WhatsApp notifications.
The explicit new-topic button retains its existing bounded daily request quota.
