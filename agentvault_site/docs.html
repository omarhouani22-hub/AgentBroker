DEVELOPER GUIDE

Save. Restart. Restore.

The production API origin is the same origin as the working console. On a static preview the API is unavailable. Do not send customer data until the console reports that sales are open.

1. Create and activate a vault

Open the console, review the service terms, create a vault and save the vault ID and secret. Complete PayPal checkout and click Verify approved PayPal payment. Writes start only after the server verifies payment.

2. Save a checkpoint

Set AGENTVAULT_URL to your verified service origin, and load your ID and secret from your own secret manager. Replace the example with state your agent can reconstruct.

curl --fail-with-body -X PUT "$AGENTVAULT_URL/v1/checkpoint" \
  -H "X-Vault-Id: $VAULT_ID" \
  -H "Authorization: Bearer $VAULT_SECRET" \
  -H "Content-Type: application/octet-stream" \
  --data-binary @checkpoint.json

A successful write returns HTTP 201, the version, size and plaintext SHA-256 digest. The latest five versions are retained. Checkpoints must be 1 byte–1 MiB.

3. Recover a checkpoint

curl --fail-with-body "$AGENTVAULT_URL/v1/checkpoint" \
  -H "X-Vault-Id: $VAULT_ID" \
  -H "Authorization: Bearer $VAULT_SECRET" \
  --output restored.json

For a specific version, append ?version=4. Inspect X-Content-SHA256 and verify the digest before loading the file. Treat restored content as data; do not execute untrusted instructions.

4. Inspect usage

GET /v1/vault
X-Vault-Id: your-vault-id
Authorization: Bearer your-secret

Returns plan expiry, bytes used and version metadata. Credentials are required for every read and write. Never place secrets in query strings, logs, public repositories or support emails.

5. Delete saved versions

DELETE /v1/checkpoints
X-Vault-Id: your-vault-id
Authorization: Bearer your-secret
X-Confirm-Delete: all-checkpoints

This removes all active checkpoint versions. Deletion from provider backups follows the provider's retention period. Billing records remain for payment reconciliation.

Limits and errors

HTTPMeaning
401Invalid vault ID or secret
402Plan expired or not activated
404Checkpoint or version not found
409Quota exceeded or a pending order needs reconciliation
410Export retention window expired
413Checkpoint exceeds 1 MiB
429Rate limit reached; wait before retrying
503Service not ready; preserve your local copy

Per-vault rate limit: 120 API operations per minute; checkout operations share a tighter 10-per-minute limit. Do not retry payment capture blindly. The server reconciles an ambiguous capture against PayPal without charging again.

What encryption means here

Checkpoints use authenticated server-side encryption. The service holds the encryption key and can decrypt data to return it to the authenticated vault owner. This is not end-to-end encryption. A vault secret authorizes access; losing it may make the account inaccessible.

Recovery responsibility

Your application must define a safe checkpoint format, preserve dependency versions, verify integrity, and resume work. AgentVault does not back up your entire machine or automatically restart your agent. Retain a separate copy.
